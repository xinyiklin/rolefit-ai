# RoleFit 0.24.0: unsigned preview beta.1

<!-- Curated preview-note source. Publication occurs only after every native build, packaged smoke, installer lifecycle, checksum, and atomic-publication gate succeeds. -->

This unsigned public preview lets AI agents run RoleFit's own AI stages and
read more of your workspace through RoleFit's local MCP server. It includes
browser extension **1.5.2** and desktop bridge API **13**, both unchanged, and
keeps the product local-first and browser-primary: there is no app account,
hosted workspace, cloud synchronization, or telemetry service.

Version 0.24.0 lets an agent analyze a posting, assess fit, polish a resume or
cover letter, draft application answers, and run the final review with
RoleFit's own requests and evidence checks, and read your cover letters, a
whole saved application, your earlier answers, and your Profile. An agent now
always records a submitted application with the resume that was sent, including
when it submits a Draft. RoleFit's own windows work as before. It remains a
preview rather than a stable release because public installers are still
unsigned, automatic updates are not implemented, and portable formats may still
change without migrations.

## Upgrading from an earlier preview

- Quit the existing RoleFit application before installing this preview.
- **From 0.22.0 or 0.23.0:** 0.24.0 reads and writes the same workspace,
  tracker, preferences, backups, and `.resume` and `.cover` files, so no backup
  step is needed to move between them.
- **From 0.21.0 or earlier:** read the 0.22.0 notes first. That preview
  renamed the app to RoleFit (on macOS, delete the old `RoleFit AI.app` after
  installing; on Windows, delete a leftover "RoleFit AI" shortcut) and gave
  the tracker a format version. The earlier previews' upgrade notes still
  apply when you skip versions.
- On Windows, run the new installer over the existing installation. It updates
  in place and keeps RoleFit's internal upgrade and local-data identity.
- On macOS, replace the existing `RoleFit.app` in Applications.
- From 0.22.0 or later, the browser extension is unchanged (1.5.2) and needs no
  reload. From 0.21.0 or earlier, reload the unpacked extension once, as the
  0.22.0 notes describe.
- Reload any RoleFit tab left open from the previous version.
- If an agent uses RoleFit's MCP server, update your RoleFit source checkout to
  0.24.0 as well, then restart the agent's MCP connection. The MCP server runs
  from the checkout, not the installer, and must match the RoleFit it talks
  to: an older MCP server's Draft submission without documents is refused by
  0.24.0, and a 0.24.0 MCP server's submission with documents is refused by
  0.23.0.
- Agent instructions that record an application as Applied without its
  resume, or submit a Draft and upload the resume afterwards (as the 0.23.0
  notes suggested), now need to send the resume's `.resume` file with the
  submission. When there is no `.resume` file for the resume that was sent,
  apply from RoleFit yourself instead.

## Before installing

- macOS 13 or later on Apple silicon is required. There is no Intel macOS
  download.
- macOS Gatekeeper will identify the app as coming from an unidentified
  developer. The app has an ad-hoc integrity signature but is not notarized or
  signed with Apple Developer ID.
- Windows SmartScreen will warn that the publisher is unknown. The installer
  is not Authenticode-signed.
- Download only from the canonical RoleFit GitHub Release and compare the file
  against `SHA256SUMS.txt` before opening it.

## New

- **Agents can run RoleFit's AI stages.** Through the MCP server, an agent can
  turn a posting into RoleFit's job brief, run Fit Assessment, ask for a Resume
  Polish proposal and accept the edits it chooses, ask for a cover-letter
  proposal, draft an answer to an application question, and run the final
  application review on a saved application. Each one sends the same request
  the app sends for that stage, on the provider, model, and effort you saved
  for it in Settings and, except for job analysis, with your Profile and the
  facts you declared. It is a provider call billed to your key, or a run of
  your CLI, and can take minutes. The results carry RoleFit's evidence
  warnings, held-back edits, and checks, as in the app, and nothing is saved
  until the agent saves it. Cancelling the call stops the provider run (what
  the provider already processed may still be billed), and each agent
  connection can have at most three running at once.
- **Agents can submit a Draft with its documents.** When an agent submits a
  Draft (or applies to a job that was skipped without applying), it now sends
  the resume that was sent, and the cover letter if there was one, and RoleFit
  saves them with the new stage or saves neither.
- **Agents can read more.** An agent can list and read your saved cover
  letters, read everything saved for one application in one call (its resume
  and cover letter, newest answers, Fit Assessment, and job brief, with what is
  missing), search the answers you saved on every application, and read your
  Profile Background and the candidate facts you declared in Settings. Your
  agent's own AI provider sees whatever the agent reads and every AI-stage
  result. The AI stages themselves send their inputs, including saved
  documents and your Profile, only to the provider set in RoleFit.

## Changed

- **An agent's submitted application always has its resume.** RoleFit now
  refuses an agent's save of an application as Applied, and an agent's first
  submission of a Draft or skipped job, unless the resume that was sent comes
  with it. RoleFit's own Apply is unchanged.
- **The MCP server handles several calls at once.** A long AI call no longer
  makes the agent's other calls wait. If the agent's app closes, RoleFit stops
  any AI run the agent started.

## Known issues

- An installed upgrade from 0.23.0 or earlier has not been tested, including
  whether saved API keys carry over. Re-entering a key in the companion
  restores it.
- Of the tools added in 0.24.0, reading a saved application's package,
  reading a cover letter, and drafting an answer have been used through a real
  agent client against RoleFit run from source, drafting an answer with its
  live provider (once returning a ready answer, once asking for a
  clarification). The other tools added or changed in 0.24.0 have not been
  used live, including job analysis, Fit Assessment, both Polishes, applying
  resume edits, the final review, the other reads, and recording a submitted
  application with its resume; they and the 0.23.0 tools were tested offline,
  and the AI stages also against a local RoleFit server up to the point where
  it would call the provider. The MCP server itself was checked with Claude
  Code and Codex 0.162.1 for 0.21.0, against a throwaway server run from
  source, not against the installed companion, other agents, or a non-default
  port.
- The MCP server runs only from a source checkout with Node 24.22 or later;
  the installers do not include it.
- Through an agent, Resume Polish always edits the sections RoleFit polishes by
  default; the agent cannot choose sections. A Fit Assessment the agent passes
  to Polish is treated as an earlier one, as a saved assessment is in the app.
- An agent drafting an answer for an application saved in RoleFit uses that
  application's saved job brief, which also lists the posting's benefits; the
  app leaves them out.
- RoleFit tells a later AI stage that resume or letter wording has open
  evidence warnings only when the agent passes those warnings on, and for the
  document as a whole rather than for each field.
- Facts, clarifications, and cover-letter details an agent enters on your
  behalf, and a resume it sends as text (including one it wrote or edited
  itself), are treated as your own evidence. The tools tell the agent to take
  them from you and to send only saved resumes or RoleFit's own edits; check
  what an agent sends.
- If an agent's app stops waiting for an AI call without cancelling it (some
  apps limit how long a tool call may take; raise that limit for RoleFit), the
  provider run can continue for up to 15 minutes, its result is lost, and it
  holds one of the agent's three runs until it ends. The three-run limit
  applies to each agent connection, not to RoleFit as a whole.
- Moving Resume Polish's Accept and Undo, and the cover letter's Accept, into
  code the MCP server shares was checked by offline tests that compare the
  result with the editor's, not by using RoleFit's editor in a browser.
- The companion's startup retry was tested only with a simulated slow
  service; it has not been observed in the running app or tested in an
  installed build. Its Overview and Settings may still briefly
  show the local service as unreachable while it starts.
- The faster first-page loading was checked in RoleFit only by its build and
  offline tests. RoleFit's editor, browser printing, and resume, cover-letter,
  and Apply PDF downloads were not rechecked in a browser after the change.
- The editor focus and zoom changes were checked in the shared editor's test
  harness with RoleFit's colors, not in the RoleFit app itself or in dark
  mode.
- On macOS, the first launch of `RoleFit.app` might ask to use RoleFit's saved
  keychain item; this has not been checked.
- The extension's PNG icons have not been checked in an installed Chrome,
  Edge, or Firefox extension.
- The newer-file notice was checked with a synthetic newer workspace through
  the server and the browser app, not with installed builds.
- The Windows installer has been tested only on the automated build machine,
  not on a separate Windows PC.
- A RoleFit tab that is already open may not show an agent's change until you
  refresh the Applications list or reload. An edit there that conflicts with
  the agent's change is refused, not saved over it.
- If an agent's save, answer, or event call times out or loses its reply, the
  write may still have landed. The tools tell the agent to read the record
  before retrying. A blind retry of an answer or event can record it twice; a
  repeated save is usually refused as a duplicate.
- The extension 1.5.1 color fixes were checked through computed styles in
  Firefox only, not in Chrome or Edge and not as an installed extension. The
  failure badge itself was not shown.
- The extension popup shows a Draft's or skipped job's stage by its internal
  name (`draft`, `not_applying`).
- The look was checked mainly in Chromium-based browsers; a Firefox smoke test
  covered Prepare, Applications, Analytics, and Appearance. It was not checked
  in Safari, and printing from the browser app was not rechecked.
- The companion's window has not been checked on macOS after the rename. Its
  native window controls do not appear in the screenshots that were checked,
  and moving the window by its top band was not checked.
- Windows High Contrast and other forced-color modes were not checked in the
  browser app or the companion; there, the companion's window controls keep
  fixed colors.
- The extension popup was checked against simulated extension APIs in a
  Chromium browser, not as an installed Chrome, Edge, or Firefox extension, and
  not with forced colors.
- The extension's in-progress badge was not checked in an installed extension;
  in Firefox the blue badge may blend into the icon.
- The Timeline button's count includes stage entries RoleFit records on its
  own, not only the ones you log.
- Moving an application to Rejected is not counted as a reply in Analytics.
  Moving a Ghosted application back to Applied skips past Interviewing even if
  it had interviews.
- Automatic Ghosted marking coordinates RoleFit tabs on the same address only.
  A tab opened on another address (for example `127.0.0.1` beside
  `localhost`) runs its own pass.
- The timeline and Analytics were checked in Chromium but not in Firefox or
  Safari.
- The companion's Backup and Restore with saved cover letters was verified
  through the server, not through the installed companion.
- Backup and restore do not yet say how many history files they left out.
- Finding CLIs installed through fnm or nvm has not been checked in an
  installed app. A CLI installed only under a non-default fnm version, or under
  a custom or legacy fnm or nvm directory, is not found.
- Deleting an application keeps its files in the workspace's
  `applications/.trash` folder. They are not in backups and RoleFit has no way
  to restore them yet.
- Backing up or restoring a workspace near the maximum through the desktop
  companion has not been verified yet. Large backups use substantial memory
  while they are built.
- The Prepare form has not been checked in Firefox, at 980 or 860 px wide, or
  with a prepared job.
- Input-method typing was checked in Chromium and Firefox but not in Safari.
- The OpenAI API's effort setting has not been run live. OpenAI documents Low
  through Max for GPT-6.1 Sol; Astra's and Luna's API levels follow the Codex
  catalog.
- The Plan and CLI/API controls were checked in Chromium but not in Firefox.
- Some single-vendor plan settings are untested best guesses: Final
  application review on either plan, and OpenAI only's Resume import.
- Claude Code 2.1.285 runs Haiku 5.5 but reports it as an unrecognized model.
- Claude Code's instructions file has run live on macOS but not yet on
  Windows.
- In a Resume proposal's Edit box, text is edited in its stored form:
  formatting shows as tags such as `<b>`, and a "<" that would start a tag
  shows as `<lt>`. Keep them as shown. Typing a new tag there adds
  formatting; to type a literal "<" before a tag name, write `<lt>`.
- Cover letter Polish treats text that looks like a formatting tag, such as
  `<b>`, as markup. In a body paragraph, Polish retries once and may then fail
  or drop that text. In a greeting or sign-off, the text becomes formatting
  when you accept the letter.
- Greenhouse job pages, iCIMS, and Dayforce still use slower parsers. Hostile
  markup served from those sites could still tie up the local server.
- PDF import was tested on synthetic resumes; accuracy on real-world layouts
  and live provider interpretation have not been measured. Two layouts read
  imperfectly, with no text lost:
  - A dated sidebar whose headings look like its entries, beside a column
    without bullets, reads as one column.
  - Some values at a tab stop stay joined to the title with a Check.
- Gap statements in the Resume proposal come from the same model that writes
  the edits. In testing, a partly met requirement was occasionally marked
  Addressed.
- During Polish again, the earlier proposal stays in the rail and its edits
  can still be accepted or discarded. Accepting one changes the document, which
  stops the new Polish.
- Outside Rippling, a posting link that redirects to a general careers page
  imports that page's text as the job; check the brief.
- A posting inside a frame from another origin is still missed when that frame
  is not a recognized job-board posting, or when the frames name more than one
  posting.
- Lever and Jobvite frames were tested only with offline fixtures, not against
  live postings.
- The extension's frame capture has not been hand-tested in an installed
  Chrome or Firefox extension.

## Included

- A native macOS download for Apple silicon (DMG and ZIP), a native Windows
  x64 installer, and a checksum file covering every published artifact.

RoleFit's browser app, loopback server, paired extension, and workspace remain
on the user's device. AI input goes directly to the provider selected for that
stage only when the user runs the workflow, or when an agent the user connected
to RoleFit's MCP server runs it; provider credentials and personal workspace
data are not part of the public release artifacts.
