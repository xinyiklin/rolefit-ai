# RoleFit AI 0.19.0: unsigned preview beta.1

<!-- Curated preview-note source. Publication occurs only after every native build, packaged smoke, installer lifecycle, checksum, and atomic-publication gate succeeds. -->

This unsigned public preview gives each submitted application a dated
timeline, flags applications that have gone quiet, adds a Ghosted stage, and
redesigns Analytics. It includes browser extension **1.4.1** and desktop
bridge API **13**; the extension changes only to name the Ghosted stage. RoleFit
stays local-first and browser-primary: there is no app account, hosted
workspace, cloud synchronization, or telemetry service.

It remains a preview rather than a stable release because public installers
are still unsigned, automatic updates are not implemented, and portable
formats may still change without migrations.

## Upgrading from an earlier preview

- **Make a `.rolefit-backup` in 0.18.0 before upgrading.** It is the only way
  back: 0.19.0 saves data that 0.18.0 and earlier cannot read.
  - 0.19.0 saves the No response settings in the workspace preferences when it
    first opens. 0.18.0 treats that preferences file as invalid and does not
    save preference changes over it.
  - A backup made in 0.19.0 does not restore in 0.18.0 or earlier, because it
    carries those settings.
  - A tracker that holds any timeline entry or a Ghosted application does not
    open in 0.18.0 or earlier.
  - These were confirmed by running 0.18.0's own file checks on 0.19.0 data,
    not by running the 0.18.0 app.
- **Backups made by 0.18.0 restore in 0.19.0.** The 0.18.0 notes describe
  restoring older backups.
- **Rolling back to 0.18.0:** reinstall 0.18.0, close every RoleFit tab, then
  restore the backup you made in 0.18.0 before upgrading. The restore replaces
  the whole workspace; your 0.19.0 workspace stays beside it as a safety copy
  that only 0.19.0 can open. Rollback has not been tested, including whether
  the Windows installer for 0.18.0 installs over 0.19.0.
- **Existing applications start their timeline with the submission date.**
  New entries begin with the first change after upgrading. An application
  skipped before this version records its Skip date as an entry when it leaves
  Skipped.
- **Applications quiet for 21 days or more show No response right away**,
  counted from the submission date. That includes Interviewing applications
  whose interviews were never logged. The flag is derived and changes nothing
  on its own. Before you turn on automatic Ghosted marking, log the latest
  interview (or a follow-up dated today or later) on applications that are
  still active, or they will be marked Ghosted.
- The earlier previews' upgrade notes still apply when you skip versions: see
  0.18.0 for backups with saved cover letters, 0.17.0 for per-field sizes,
  model renames, and API effort, 0.16.0 for Antigravity and GPT-5.5, 0.14.0
  for the added font families, and 0.11.0 for upgrades from 0.10.0 or earlier.
- **Reload the unpacked extension once** so it picks up extension 1.4.1.
  Firefox removes temporary add-ons when it quits, so load it again after a
  restart.
- Reload any RoleFit tab left open from the previous version.
- Quit the existing RoleFit application before installing this preview.
- On macOS, replace the existing `RoleFit AI.app` in Applications.
- On Windows, run the new installer over the existing installation. The
  installer retains RoleFit's internal upgrade and local-data identity.
- The installed companion continues to use the existing RoleFit workspace and
  provider configuration.

## Before installing

- macOS Gatekeeper will identify the app as coming from an unidentified
  developer. The app has an ad-hoc integrity signature but is not notarized or
  signed with Apple Developer ID.
- Windows SmartScreen will warn that the publisher is unknown. The installer
  is not Authenticode-signed.
- Download only from the canonical RoleFit GitHub Release and compare the file
  against `SHA256SUMS.txt` before opening it.

## New

- **An application timeline.** Each submitted application keeps a dated record
  of stage changes after submission, interviews (Recruiter screen, Hiring
  manager, Technical, Assessment, Panel / onsite, Final, or Other, numbered by
  date), employer responses, and follow-ups you sent; interviews, responses,
  and follow-ups each take an optional note. Open it from the Timeline button on Application Detail's status card.
  Each entry saves on its own; saving a new interview on an Applied
  application moves it to Interviewing, and leaving with an unsaved entry asks
  first. Dates are whole days, and an application holds up to 60 entries.
- **No response.** An Applied or Interviewing application with no activity for
  your **Mark as Ghosted after** setting (21 days by default, 7 to 180) is
  flagged No response in Applications, Application Detail, and Analytics. A
  scheduled interview or a follow-up planned for today or later keeps it
  fresh.
- **A Ghosted stage.** Mark an application Ghosted from its row menu or stage
  control, mark flagged ones together from Analytics' Needs your attention
  list, or turn on **Mark as Ghosted automatically** in Settings > Automation
  (also on Analytics as Mark automatically; off by default). An automatic mark is dated the day the threshold passed and skips
  the application open in Application Detail in that tab. Logging an interview
  reopens a Ghosted application as Interviewing, and moving it back to Applied
  restarts its count.
- **A redesigned Analytics page**: the period's applications by stage, with
  the total compared to the previous period; weekly or monthly activity stacked by stage (select a
  column to list it); how many applications may be ghosted and how long open
  ones have been quiet; the stage distribution, where selecting a stage opens
  those applications; a Needs your attention list with each one's next step;
  and upcoming interviews and follow-ups. Periods are 8, 12, or 26 weeks, or
  all time by month.

## Changed

- **The calendar shows interviews**, and the Applications inspector shows the
  latest and next interview.
- **A stage change on a submitted application is always recorded.** The local
  server refuses one that does not add a matching timeline entry.
- **The extension popup names the Ghosted stage** for a tracked posting.

## Fixed

- **Tracker dates keep their calendar day in every time zone**, including
  UTC+13 and UTC+14, where a saved date could move by a day. Some existing
  dates, such as a submission recorded late in the evening west of UTC, now
  show their correct local day, one day off from before.
- **A malformed tracker date no longer breaks the form**; it is ignored.

## Known issues

- The Timeline button's count includes stage entries RoleFit records on its
  own, not only the ones you log.
- Moving an application to Rejected is not counted as a reply in Analytics.
  Moving a Ghosted application back to Applied skips past Interviewing even if
  it had interviews.
- Automatic Ghosted marking coordinates RoleFit tabs on the same address only.
  A tab opened on another address (for example `127.0.0.1` beside
  `localhost`) runs its own pass.
- The timeline and the redesigned Analytics were checked in Chromium but not
  in Firefox or Safari.
- The companion's Backup and Restore with saved cover letters was verified
  through the server, not through the installed companion.
- Backup and restore do not yet say how many history files they left out.
- Finding CLIs installed through fnm or nvm has not been checked in an
  installed app. A CLI installed only under a non-default fnm version, or under
  a custom or legacy fnm or nvm directory, is not found.
- Deleting an application keeps its files in the workspace's
  `applications/.trash` folder. They are not in backups and RoleFit has no way
  to restore them yet.
- Backing up or restoring a workspace near the maximum through the desktop
  companion has not been verified yet. Large backups use substantial memory
  while they are built.
- The Prepare form has not been checked in Firefox, at 980 or 860 px wide, or
  with a prepared job.
- Input-method typing was checked in Chromium and Firefox but not in Safari.
- The OpenAI API's effort setting has not been run live. OpenAI documents Low
  through Max for GPT-6.1 Sol; Astra's and Luna's API levels follow the Codex
  catalog.
- The Plan and CLI/API controls were checked in Chromium but not in Firefox.
- Some single-vendor plan settings are untested best guesses: Final
  application review on either plan, and OpenAI only's Resume import.
- Claude Code 2.1.285 runs Haiku 5.5 but reports it as an unrecognized model.
- Claude Code's instructions file has run live on macOS but not yet on
  Windows.
- In a Resume proposal's Edit box, text is edited in its stored form:
  formatting shows as tags such as `<b>`, and a "<" that would start a tag
  shows as `<lt>`. Keep them as shown. Typing a new tag there adds
  formatting; to type a literal "<" before a tag name, write `<lt>`.
- Cover letter Polish treats text that looks like a formatting tag, such as
  `<b>`, as markup. In a body paragraph, Polish retries once and may then fail
  or drop that text. In a greeting or sign-off, the text becomes formatting
  when you accept the letter.
- Greenhouse job pages, iCIMS, and Dayforce still use slower parsers. Hostile
  markup served from those sites could still tie up the local server.
- PDF import was tested on synthetic resumes; accuracy on real-world layouts
  and live provider interpretation have not been measured. Two layouts read
  imperfectly, with no text lost:
  - A dated sidebar whose headings look like its entries, beside a column
    without bullets, reads as one column.
  - Some values at a tab stop stay joined to the title with a Check.
- Gap statements in the Resume proposal come from the same model that writes
  the edits. In testing, a partly met requirement was occasionally marked
  Addressed.
- During Polish again, the earlier proposal stays in the rail and its edits
  can still be accepted or discarded. Accepting one changes the document, which
  stops the new Polish.
- Outside Rippling, a posting link that redirects to a general careers page
  imports that page's text as the job; check the brief.
- A posting inside a frame from another origin is still missed when that frame
  is not a recognized job-board posting, or when the frames name more than one
  posting.
- Lever and Jobvite frames were tested only with offline fixtures, not against
  live postings.
- The extension's frame capture has not been hand-tested in an installed
  Chrome or Firefox extension.

## Included

- Native macOS downloads for Apple silicon and Intel, plus a native Windows x64
  installer and a checksum file covering every published artifact.

RoleFit's browser app, loopback server, paired extension, and workspace remain
on the user's device. AI input goes directly to the provider selected for that
stage only when the user runs the workflow; provider credentials and personal
workspace data are not part of the public release artifacts.
