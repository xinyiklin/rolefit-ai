# RoleFit AI 0.9.1: unsigned preview beta.1

<!-- Curated preview-note source. Publication occurs only after every native build, packaged smoke, installer lifecycle, checksum, and atomic-publication gate succeeds. -->

This unsigned public preview is a fix release for RoleFit 0.9.0. It includes
browser extension **1.2.1** and desktop bridge API **13**, both unchanged, and
keeps the product local-first and browser-primary: there is no app account,
hosted workspace, cloud synchronization, or telemetry service.

Version 0.9.1 fixes three issues in Answers and Prepare and adds no new
features. It remains a preview rather than a stable release because public
installers are still unsigned, automatic updates are not implemented, and
portable formats may still change without migrations.

## Upgrading from an earlier preview

- **From 0.9.0:** 0.9.1 reads and writes the same workspace, tracker, settings,
  and backups as 0.9.0, so no backup step is needed to move between them.
- **From 0.8.0 or earlier:** the RoleFit 0.9.0 preview's upgrade notes also
  apply. Trackers, settings, and backups saved by 0.9.x do not open in 0.8.0,
  so create a `.rolefit-backup` in 0.8.0 before upgrading if you may need to
  roll back.
- Reload any RoleFit tab left open from the previous version before editing.
- Quit the existing RoleFit application before installing this preview.
- On macOS, replace the existing `RoleFit AI.app` in Applications.
- On Windows, run the new installer over the existing installation. The
  installer retains RoleFit's internal upgrade and local-data identity.
- The installed companion continues to use the existing RoleFit workspace and
  provider configuration.
- The browser extension is unchanged (1.2.1); no reload is needed.
- Save important standalone cover letters as `.cover` files separately. The
  current `.rolefit-backup` allowlist does not include saved cover-letter
  variants.

## Before installing

- macOS Gatekeeper will identify the app as coming from an unidentified
  developer. The app has an ad-hoc integrity signature but is not notarized or
  signed with Apple Developer ID.
- Windows SmartScreen will warn that the publisher is unknown. The installer
  is not Authenticode-signed.
- Download only from the canonical RoleFit GitHub Release and compare the file
  against `SHA256SUMS.txt` before opening it.

## Fixed

- **Answers no longer drafts from the bundled Starter sample on Retry.** If a
  draft failed or was stopped and you then opened the Starter template, Retry
  in the Answers progress card sent the sample's content as your resume. It now
  stops with "Add your resume first.", as sending a question and the Answers
  tab's own Retry already did. This applies while nothing is saved for the
  current job yet; once its Draft or application exists, opening the Starter
  still counts as a resume. That is a known issue for a later release.
- **The first Answers Save keeps a Link you already chose.** If you prepared a
  posting again, chose Link for a matching application, and then stopped that
  preparation, the first Save in Answers now links the new Draft to that
  application's posting group, as Polish, Apply, and Skip & save job already
  did. If you chose Keep separate instead, the Draft is saved unlinked. Before,
  the Draft was saved unlinked and a later Apply did not link it; Drafts saved
  that way by 0.9.0 stay unlinked.
- **Prepare's Resume Polish matches the Resume tab.** A locked Education or
  contact section left set to Polish no longer counts as a section to polish,
  so Prepare no longer offers Polish for a resume whose only Polish sections
  are locked. When no editable section is set to Polish and the Polish provider
  is ready, the Resume card says so instead of showing an earlier Polish
  status.

## Included

- Native macOS downloads for Apple silicon and Intel, plus a native Windows x64
  installer and a checksum file covering every published artifact.

RoleFit's browser app, loopback server, paired extension, and workspace remain
on the user's device. AI input goes directly to the provider selected for that
stage only when the user runs the workflow; provider credentials and personal
workspace data are not part of the public release artifacts.
